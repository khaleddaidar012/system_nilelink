# Unified activity log

The D1 deployment exposes `/admin/activity` through the admin header and sidebar. Active staff and managers can read it; customers, inactive users and anonymous visitors cannot. Authorization re-reads the current account rather than trusting a stale token role. The API is GET-only and never returns unrelated backup audit records or raw source documents.

New workflow and account mutations append an audit record in the same D1 transaction as the business change. Failed writes and optimistic-concurrency conflicts roll back their audit too. The workflow store and account repository use request-local actor context to prevent attribution leaking between concurrent requests. Multi-file uploads record each document. Document downloads are recorded after storage ownership and integrity checks.

Coverage: customer registration and login; profile/contact changes; staff accounts, roles and customer status; document uploads, downloads, review, archive and warnings; requests, quotations, services and pricing; invoices, payments, financial delivery requests and document categories; mailbox connection/disconnection. Financial delivery events describe queueing, not proof of delivery. Mailbox contents, recipients and read state are not collected. The existing backup audit and background expiry/transport histories remain separate. Viewing a page or marking a notification read does not flood the business log.

Records preserve actor ID, name, username and role at the time of the action, target ID/type/label, timestamp and a strict allowlist of changed field names. Passwords, tokens, credentials, raw request bodies, document contents and before/after account snapshots are never copied. New events use `activityVersion: 1` in the existing `system_audit_logs` table, so they are included in existing full database backups without a migration. The event discriminator includes its unique ID to respect the original table's unique event/job constraints. No historical actions are fabricated or backfilled.

Search is parameterized and escapes LIKE wildcards. Filters support actor role, action category and Cairo business dates including midnight DST transitions. Results are bounded to 30 per page, ordered by time and ID. The interface refreshes every 30 seconds while visible, aborts outdated filter requests and retains an explicit error state on refresh failure. There are no UI actions or API routes to edit or delete history.
