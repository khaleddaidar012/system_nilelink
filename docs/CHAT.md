# Staff and customer conversations

`/admin/chat` and `/portal/chat` share an RTL-friendly conversation workspace. Staff can start one-to-one chats with active colleagues or customers and create any number of named internal groups. Customers see an inbox with a separate conversation for each staff member who contacts them; they cannot browse the directory, start groups, join internal discussions or inspect anyone else's conversation.

The header shows an unread badge and an in-app toast for new unread messages outside the chat screen. No desktop permission or external messaging service is used. Open threads refresh every four seconds, the inbox every ten seconds, and the header every fifteen seconds while the page is visible. No invented online or typing status is displayed. The workspace supports replies to an existing message, per-member read markers, earlier history, sender identity, Cairo timestamps, searching the inbox and a staff/customer directory. Group owners and participating administrators can rename groups or add/remove staff. The owner remains a member. Groups contain staff only.

Every API call resolves the current stored account and membership. Internal conversation audiences stay internal after a role change. A customer conversation requires a staff participant; two customers cannot acquire a peer channel by changing a former employee's role. Removed members lose access immediately. Private message content is not written to the global activity log; group creation and changes have metadata-only audit entries.

Messages are plain text, 1–4000 characters. The server chooses sender ID/name/role, timestamps and sequence. A UUID supplied for each send makes retries idempotent; reusing it for a different payload is rejected. Room revision guards and unique sequence constraints make concurrent sends explicit conflicts instead of overwriting messages. A response lost after commit is resolved by its retry ID. The interface keeps unconfirmed sends visible with a retry button using the same ID. Read markers can only advance to known messages and never move backwards. Read indicators are based on actual recipient read markers. This release supports text and replies; it does not upload attachments, make calls or forward messages to external email/WhatsApp.

Migration `0006_chat.sql` adds conversations, memberships and messages without changing business tables. The reviewed extension in `backup-schema.mjs` permits exactly this schema alongside the original 23 tables. Encrypted cloud backups capture all 26 tables; previous backups can still be verified/restored locally. Unknown or partial schema changes remain an error. The original backup byte/record safety limits remain in force and need capacity review as message history grows; the existing monitor reports failed or uncertain backups. No conversation retention or silent deletion was introduced.

Tests cover customer inbox separation, private membership, staff-only groups, live role revocation, reply isolation, ordered pagination, read markers, concurrent sends, duplicate retries, uncertain commit responses, local backup/restore including messages and the reviewed schema extension.
