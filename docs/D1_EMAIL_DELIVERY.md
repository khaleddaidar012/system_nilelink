# إرسال البريد على D1

إرسال البريد الفعلي يستخدم Resend والنطاق `nilelinklogistics.com`. التحقق من المفتاح والنطاق يتم بطلب قراءة، ولا تُعرض قيمة المفتاح في التقرير. يتم تثبيته كـCloudflare Secret باسم `RESEND_API_KEY`، مع المتغيرات `EMAIL_PROVIDER=resend` و`EMAIL_FROM` و`EMAIL_TO` و`EMAIL_DELIVERY_ENABLED=true`.

مدخل التشغيل يسمح لمسارات البريد بالوصول إلى تحقق التطبيق عند تفعيل الخاصية. صلاحيات المستخدم والتحقق من المدخلات تبقى مطلوبة. تظل seed والـAgent القديم محجوبتين.

## المسارات

- رسائل التواصل وطلبات عرض السعر ترسل عبر مزوّد البريد.
- التسجيل يرسل رابط تحقق؛ إذا فشل الإرسال يحتفظ بالحساب ويعيد `verificationEmailSent=false`، ويمكن طلب كود جديد.
- استرجاع كلمة المرور بالرابط يرسل الرابط الفعلي؛ الأكواد تستخدم نفس مزوّد البريد ولا تُعرض أو تُسجل في الإنتاج. فشل المزوّد يعيد فشلًا بدل نجاح وهمي.
- الفواتير وكشوف الحساب تنشئ سجل إرسال فعليًا، وتراجع الصلاحيات واللقطة وتولد مرفق PDF ثم تمرّر مفتاح idempotency ثابتًا إلى Resend. قبول الرسالة يسجل الإيصال، ويحدّث حالة الفاتورة عند الحاجة؛ إعادة الطلب لا ترسلها مجددًا. الحالات غير المؤكدة لا تُعاد تلقائيًا، ولا يُعاد إرسال طوابير المعاينة القديمة.
- تحذير تجديد مستند عبر البريد يرسل فعليًا ويسجل الإيصال. تحذيرات WhatsApp وmulti ترفض قبل إنشاء طابور عند غياب تكاملها الفعلي.

قبول المزوّد لا يثبت وضع الرسالة في Inbox أو قراءتها. بطاقة البريد تعرض تهيئة API بدل ادعاء مراقبة SMTP/IMAP الخاصين بسيرفر Windows.

## التحقق

السجل الشامل `live-email-full-suite.tap` داخل مجلد first-launch الخاص: 226/226 ناجحة. بعد إصلاح ربط مسار المعاينة المحلي بالبناء، نجحت 26/26 لاختبارات البريد وعمليات الإرسال؛ وضع المعاينة المحلي مرفوض في production. اختبارات النقل تحققت من مرفق PDF ومفتاح منع التكرار وفشل المزوّد والإيصالات، دون إرسال إلى أشخاص.

أذن المستخدم برسالة اختبار واحدة إلى `info@nilelinklogistics.com`. الأمر التالي يختبر مسار التواصل المنشور مرة واحدة، ويسجل المحاولة قبل الإرسال لمنع إعادة إرسال تلقائية عند فقد النتيجة:

```powershell
node --use-system-ca scripts/d1/validate-live-email.mjs --execute
node --use-system-ca scripts/d1/validate-live-email.mjs --inspect
```

النتيجة الفعلية في `.private/d1-migration/first-launch/email-activation/test-email.json`؛ وجود التعليمات هنا وحده ليس إثباتًا لتنفيذها. `--inspect` يقرأ حالة الرسالة من Resend دون إرسال جديد.

## WhatsApp

القيم القديمة بالمشروع تجريبية، ولا تثبت وجود حساب إرسال. لتوصيل أكواد WhatsApp يلزم رقم إرسال مسجل وقالب تحقق معتمد وبيانات الحساب الفعلية. تُضبط `WHATSAPP_PHONE_NUMBER_ID` و`WHATSAPP_OTP_TEMPLATE` و`WHATSAPP_OTP_LANGUAGE` و`WHATSAPP_GRAPH_VERSION` حسب إعداد الحساب، ويُحفظ `WHATSAPP_API_TOKEN` كـSecret فقط. لا تُخمن نسخة Graph API أو بيانات القالب. مسار الأكواد يدعم قالب تحقق برمز في body وزر نسخ الكود، ويرفض غياب الإعداد أو إيصال الخدمة. تحذيرات المستندات تحتاج قالب إشعار مستقل وربطًا إضافيًا؛ لا تُعلن مفعّلة بوجود توكن فقط.
