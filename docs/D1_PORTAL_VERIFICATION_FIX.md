# حل الرجوع إلى شاشة التوثيق — 22 أكتوبر 2026

كان بريد المستخدم موثقًا في D1 وحالته active، بينما تحمل جلسة دخوله القديمة emailVerified=false. middleware يقرأ الجلسة الموقعة فيعيده إلى صفحة التوثيق. كذلك قد يحتفظ تنقل Next بتحويل جرى تحميله قبل التوثيق. حالة الشركة unverified مستقلة عن توثيق البريد، ولا تستلزم تفعيل الخدمات تلقائيًا.

تستخدم جميع أزرار متابعة البوابة داخل VerificationFlow الآن POST refresh لإعادة إنشاء claims من الحالة الحالية في D1، ثم GET me غير مخزن للتحقق من البريد. بعد النجاح تنفذ انتقالًا كاملًا إلى عنوان البوابة بلغة المستخدم، فتُطرح التحويلات القديمة المحملة مسبقًا. أثناء الطلب يتعطل الزر، وعند الفشل تظهر رسالة بدل تكرار الانتقال. لا يُشترط توثيق WhatsApp لدخول البوابة، ولا تتغير حالة الشركة أو صلاحيات الخدمات.

بعد رابط توثيق البريد يصدر handler جلسة محدثة فقط إذا كانت الجلسة الحالية تخص نفس صاحب الرابط. لا يُسجل الدخول تلقائيًا لزائر مجهول أو لحساب آخر عند فتح رابط شخص مختلف. تحديث التوثيق وتسجيل الدخول يظلان عمليتين منفصلتين في هاتين الحالتين.
