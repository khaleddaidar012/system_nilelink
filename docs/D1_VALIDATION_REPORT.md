## ما تحقق فعليًا في الجولة الحالية

- تعديل مسودة الفاتورة وحفظ حقولها الإضافية، ثم منع التعديل والأرشفة بعد التأكيد.
- وصول طلبَي دفعة بنفس المفتاح في الوقت نفسه نتج عنه دفعة واحدة وتغيير واحد للرصيد؛ تغيير قيمة الطلب مع المفتاح نفسه رُفض.
- دفعتان مختلفتان متنافستان لا تتجاوزان المستحق؛ مجموع الدفعات طابق المدفوع والمتبقي، وإلغاء فاتورة مدفوعة رُفض دون تغييرها.
- إلغاء فاتورة غير مدفوعة وأرشفة مسودة احتفظا بالبنود والرموز والسجل السابق.
- تغيير claims داخل JWT لم يتجاوز صلاحيات المستخدم المخزنة؛ العميل الآخر لم ير الفاتورة.
- حقن فشل داخل معاملة إنشاء الفاتورة أدى إلى rollback للفاتورة والسجل معًا على D1 الفعلية.
- قراءة الإشعار بالتزامن حفظت هوية القارئين، ورفضت العميل الأجنبي.
- حقن فشل الملف الثاني نظف بايتات الملف الأول غير المعتمد ولم يترك metadata أو journal غير محسوم.
- رفعان متنافسان احترما حد المستندات: اعتمد ملف واحد وظلت بايتاته موجودة في R2، دون بقايا journal.

الفشل في هذه الاختبارات حُقن في كود معمل الاختبار؛ لم نقطع خدمة حقيقية أو نحاكِ عطلًا لدى عملاء الموقع. كل الكتابات البعيدة كانت في موارد E2E الاصطناعية، وليس قاعدة نسخة النقل أو MongoDB.
