# Per-employee mailbox — 25 October 2026

The staff sidebar links to `/admin/mailbox`. Its compact Email control opens a fixed-size, scrollable preview of the newest Inbox messages, with unread markers and direct links to open a selected message in the mailbox page. The page connects one MailEnable mailbox per active staff user, with Inbox/folders, paginated message lists, HTML or plain-text viewing, reply threading, compose and attachments. HTML email is shown in a sandboxed frame that disables scripts/forms and permits HTTPS or inline images; CID images are inlined from bounded message attachments. The server resolves the owner from the signed session and re-reads the user's current role/status from D1 for every operation. It never accepts an owner ID from the browser. Mailbox connection passwords are encrypted with AES-GCM and owner/email-bound authenticated data; website passwords and customer verification are separate.

The independent `mail-agent/` service runs on the MailEnable Windows server. HTTPS requests from Workers are body-signed with a timestamp and replay-protected nonce. The agent connects to IMAP/SMTP over certificate-verified TLS, forces the From address to the authenticated mailbox, and never logs raw mail/credential errors. It binds to loopback and should be reached through a permanent Cloudflare Tunnel. A private Windows installation ZIP is prepared under `.private/d1-migration/first-launch/mailbox/`. The two Worker secrets were installed without displaying their values. `MAILBOX_AGENT_URL` is deliberately unset until the operator installs and exposes the connector securely.

No D1 tables or migrations were added: the encrypted connection profile is stored in the existing user's JSON document. Existing full-data backups include it automatically, but recovery also needs the separate mailbox-encryption key in the private Worker-secrets file. No inbox content is stored in D1.

Read state uses explicit IMAP `\\Seen` updates after a successful message fetch. UID and UIDVALIDITY are required for reading/marking/downloading so mailbox recreation cannot act on a different message with a reused UID. Successful read operations update the sidebar immediately; visible pages poll once per minute for external mail changes. New unread-count increases show an in-app toast. No sample messages or simulated mail delivery appear when the connector is unavailable.

SMTP sends use per-owner request IDs persisted before dispatch. Retries with identical IDs return confirmed acceptance or an uncertain-outcome error; they never automatically resend a possibly accepted message. Sent-copy failures and partial recipient acceptance are reported separately. The state directory must survive service updates.

Validation: 242 root D1 tests passed, six separate mail-agent tests passed, TypeScript passed, Windows installer syntax passed. Tests cover tenant/role isolation, credential encryption and AAD tampering, HMAC replay protection, UIDVALIDITY, actual local HTTP authentication boundaries, uncertain-send idempotency, and failed Sent-copy handling. All transport tests use mocks and sent no real messages. The live setup-readiness validation must continue to report mail reading/sending **not tested live** until the Windows connector is installed and an account is explicitly connected.

The website UI is deployed. Install the updated private `NileLink-MailAgent-html-email-update.zip` package on the Windows mail server to enable HTML and inline-image responses, and HTML sending for the opt-in employee signature. The current agent package must be updated separately from the Cloudflare website. Do not change the Worker endpoint, mailbox credentials, TLS settings or tunnel while updating the service.

## Edge request redirects

The mailbox gateway uses `redirect: "manual"` because the deployed edge Request implementation rejects `redirect: "error"` before making a request. A 3xx response is rejected explicitly; credentials must never be forwarded to a Location target. The regression test exercises both a successful response and a 302 without following it. `global_fetch_strictly_public` was tested and did not address this failure, so the previous compatibility flags were restored.
