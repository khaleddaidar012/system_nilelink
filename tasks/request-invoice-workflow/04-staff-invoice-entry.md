# 04 — متابعة وإعداد الفاتورة من داخل الشحنة والطلب

الحالة: لم تبدأ. يعتمد على: 01. التالي: 05، 06، 07.

## المطلوب

من تفاصيل الشحنة أو الطلب يستطيع الأدمن أو الموظف المسؤول المخول فتح الفاتورة الحالية وإعدادها مباشرة، أو اختيار/إنشاء فاتورة وربطها، دون إعادة إدخال البيانات أو إنشاء نظام مالي آخر.

## قائمة التنفيذ

- [ ] فحص نقاط الدخول القائمة في `RequestInvoices` ومكونات بيانات الشحنات قبل إضافة زر جديد.
- [ ] عرض الفاتورة الحالية الواحدة وحالتها ورقمها، وزر فتح/إعداد بحسب الصلاحية.
- [ ] إتاحة اختيار فاتورة لنفس العميل أو إنشاء/فتح فاتورة الشحنة، مع تطبيق الاستبدال من مهمة 01.
- [ ] الاحتفاظ بسياق الشحنة والطلب والعميل عند التنقل، ورابط عودة صحيح للصفحة التي بدأت منها.
- [ ] دعم الحفظ التدريجي دون إجبار اكتمال المراحل، وإظهار أخطاء الحفظ الدقيقة دون مسح المدخلات.
- [ ] المعاينة والنشر يظلان مستقلين: مرحلة مالية واحدة مكتملة على الأقل وسعر بيع موجب ومسودة محفوظة، ثم معاينة وتأكيد وصلاحية النشر.
- [ ] عند وجود نسخة منشورة، إعداد التعديلات بإصدار مراجعة؛ لا تعديل صامت للمستند الذي يراه العميل.
- [ ] الموظف المسؤول لا يحصل تلقائيًا على صلاحية مالية جديدة؛ تستخدم صلاحيات الحسابات والإنشاء والتعديل والنشر الحالية.
- [ ] إذا كانت علاقة الطلب بالشحنة ناقصة، اختيار صريح بدل ربط تلقائي بالاسم أو رقم حجز غير موثوق.

## ملفات البداية

- `components/admin/shipments/RequestInvoices.tsx`، `components/admin/shipments/ShipmentInvoiceWorkspace.tsx` ومكونات جدول الشحنات الحالية.
- `lib/shipments/invoice-privacy.ts` و`lib/auth/accounts-access.ts`.
- صفحات تفاصيل الطلب والشحنات ومسارات حسابات الشحنات.

## اختبارات ومعايير القبول

- [ ] مسار من الشحنة للفواتير والعودة دون تكرار فاتورة الشحنة الأساسية.
- [ ] من الطلب تظهر فاتورة حالية واحدة بعد الربط أو الإنشاء أو الاستبدال.
- [ ] تغيير البحث في قائمة الشحنات/الفواتير لا يسمح بإرسال اختيار قديم مخفي عن المستخدم.
- [ ] الموظف الذي يستطيع التشغيل فقط لا يرى أو يعدّل الفاتورة دون الصلاحية المالية.
- [ ] غير الأدمن لا يرى الربح في الواجهة أو الاستجابة أو سجل التدقيق المعروض.
- [ ] العميل لا يرى أي تغيير Draft قبل النشر، بما في ذلك مسودة مراجعة فاتورة منشورة.
