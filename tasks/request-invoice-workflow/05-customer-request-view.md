# 05 — تتبع الطلب والخدمات ومعاينة الفاتورة عند العميل

الحالة: لم تبدأ. يعتمد على: 01، 02، 03، 04. التالي: 09.

## المطلوب

صفحة الخدمات المطلوبة/طلبات الخدمة تعرض تقدم كل طلب وخدماته الفعلية، مع معاينة الفاتورة الحالية عند نشرها فقط. تفاصيل الطلب تعرض نفس البيانات بصورة أوسع دون حالات متناقضة.

## قائمة التنفيذ

- [ ] إضافة ملخص المرحلة الحالية وحالة كل خدمة مطلوبة في قائمة طلبات العميل وتفاصيل الطلب.
- [ ] إظهار UCR/ACID الصالح للعملية وحالة التجهيز حسب المسار المعتمد.
- [ ] المسار المباشر لا يعرض انتظار قبول عرض سعر غير مطلوب؛ المسار الاختياري بعرض سعر يحتفظ بخطواته.
- [ ] زر باسم «معاينة الفاتورة» يظهر فقط عند وجود فاتورة حالية منشورة مصرح بها للعميل.
- [ ] لا تظهر مسودة أو عدّاد لها أو بيانات تعريف/مبالغ منها داخل طلب العميل أو قائمة الخدمات.
- [ ] استجابة الخادم تختار الفاتورة الحالية فقط بعد مهمة 01، لا آخر فاتورة عشوائيًا من قائمة.
- [ ] عند استبدال منشورة بمسودة، يختفي زر معاينة الفاتورة الحالية من الطلب حتى النشر؛ لا تُحذف الفاتورة القديمة من السجل المالي المشروع.
- [ ] عند وجود مراجعة Draft لنفس الفاتورة المنشورة، يستمر عرض آخر Snapshot منشور حتى نشر المراجعة.
- [ ] تحديث العرض عند الرجوع للصفحة ودوريًا/عند استقبال تحديث بالطريقة الحالية، مع حالات تحميل وفشل واضحة.
- [ ] الحفاظ على روابط النسخة المنشورة وPDF والتحقق من الملكية على الخادم.

## اختبارات ومعايير القبول

- [ ] Draft لا تنتج زر معاينة أو معلومة عن المبلغ في أي من صفحات العميل أو API.
- [ ] Publish ينتج زرًا صحيحًا في قائمة الطلبات والتفاصيل للعميل المرتبط فقط.
- [ ] رابط تخميني لطلب أو فاتورة أو PDF عميل آخر يُرفض.
- [ ] طلب خدمة واحدة يعرضها فقط، وطلب خدمات متعددة يعرض الحالات المسجلة فعلًا.
- [ ] طلب بلا فاتورة يعمل طبيعيًا، وفشل جلب البيانات لا يُعرض كأنه لا توجد فواتير.
- [ ] إعادة تعيين الفاتورة أو نشر مراجعة يتحدث في الواجهة دون استخدام بيانات Draft بدل النسخة المنشورة.
- [ ] اختبار العربية والإنجليزية والموبايل وRTL/LTR.
