# 07 — إشعارات تحديث الفواتير وعدّاد الحسابات بالقائمة الجانبية

الحالة: لم تبدأ. يعتمد على: 01، 04، 06. التالي: 09.

## المطلوب

تحديثات الفواتير تظهر كإشعارات/عداد غير مقروء في القائمة الجانبية اليمنى بالعربية والموضع المقابل بالإنجليزية، خصوصًا «الحسابات». الأدمن والموظف المخول يشاهدان التحديثات المسموحة لهما. فتح القسم يصفّر ما تمت قراءته فقط، وأي تحديث لاحق يعيد العدّاد.

## أحداث مقترحة ضمن المطلوب

- إنشاء مسودة، حفظ تعديل فعلي، ربط/استبدال فاتورة، النشر، بدء مراجعة، نشر المراجعة، وتغيير حالة مالي معتمد إن كان موجودًا في النظام.
- لا حدث لمجرد GET أو إعادة تحميل أو حفظ متطابق بلا تغيير أو إعادة نفس الربط.
- حدد سياسة مشاهدة تحديث المستخدم نفسه في 00، وطبّقها باتساق دون عدّادات وهمية.

## قائمة التنفيذ

- [ ] مراجعة المصدر الحالي `workspaceSections` وعلامات `workspaceSeen` قبل إضافة قسم جديد.
- [ ] ربط رابط `/admin/shipment-invoices` بعدّاد الحسابات؛ معالجة علاقته بـ`/admin/invoices` لمنع العد المزدوج أو خلط القسمين.
- [ ] استخدام أحداث مالية/سجل تدقيق موثوق بدل الاعتماد على تاريخ إنشاء الفاتورة وحده؛ الفاتورة القديمة المعدلة يجب أن تولد تحديثًا جديدًا.
- [ ] تخزين حالة القراءة لكل مستخدم على الخادم، لا localStorage فقط أو علامة مشتركة لكل الموظفين.
- [ ] تعليم الأحداث المعروضة فقط كمقروءة باستخدام watermark/نسخة مناسبة؛ حدث يصل أثناء فتح الصفحة لا يضيع.
- [ ] توحيد اللون والشكل مع عدّادات الإشعارات المعتمدة في المشروع، ودعم الشريط المفتوح والمغلق والهوفر.
- [ ] مراعاة صلاحيات الحسابات والصلاحيات التفصيلية، وتحديثها فور سحبها؛ لا عدّاد يكشف نشاطًا لقسم غير مسموح.
- [ ] تفاصيل الإشعار مفهومة: ما الذي تغير، رقم الفاتورة/الطلب، من عدله، ومتى، ورابطه. لا أرباح لغير الأدمن ولا payload مالي زائد.
- [ ] ربط العدّاد بكروت مساحة العمل ومركز الإشعارات حيث يناسب التصميم الحالي، دون إنشاء منظومة إشعارات موازية.

## ملفات البداية

- `lib/activity/workspace.ts`، `lib/activity/record.ts`، `components/admin/WorkspaceActivity.tsx`.
- `components/admin/AdminSidebar.tsx`، `components/admin/AdminExperienceContext.tsx`، وصفحة مساحة العمل.
- `app/api/admin/workspace-activity` ومسارات الإشعارات وسجل التدقيق الحالي.
- `lib/workflows/shipment-invoices.ts` و`lib/shipments/request-invoices.ts`.

## اختبارات ومعايير القبول

- [ ] تعديل فاتورة قديمة/نشرها يزيد العدّاد، لا إنشاء الفاتورة فقط.
- [ ] فتح الحسابات يصفر أحداث المستخدم المقروءة، ولا يصفر عدّاد مستخدم آخر.
- [ ] حدث متزامن مع القراءة يبقى جديدًا؛ تحديث لاحق يعيد العداد.
- [ ] إعادة تسجيل الدخول أو النشر البرمجي لا يعيد جميع الأحداث القديمة كجديدة دون سبب.
- [ ] لا أرقام أو تفاصيل حسابات لموظف بلا صلاحية، ولا ربح لغير الأدمن.
- [ ] عمل العدّاد في RTL/LTR والشريط المطوي والمفتوح والموبايل.
