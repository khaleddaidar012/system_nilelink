# 08 — إصلاح ترجمة حالة الفاتورة وعرض العملة

الحالة: لم تبدأ. يعتمد على: 00. التالي: 09.

## المشاكل المرئية في الصور

1. ظهور `PORTAL.FINANCIALS.STATUS.CONFIRMED` بدل اسم الحالة في جدول العميل ومعاينة الفاتورة.
2. جدول الفواتير يعرض `$11,000` لفاتورة عملتها EGP، بينما الملخص والمعاينة يظهران EGP.

هذه عيوب عرض لا تستدعي تغيير مبالغ الفاتورة أو قاعدة بياناتها أو إعادة نشرها.

## قائمة التنفيذ

- [ ] حصر قيم الحالة المالية الحالية: Draft داخليًا، confirmed، sent، partially_paid، paid، overdue، cancelled بحسب مسار العرض.
- [ ] تحديد ترجمة واضحة للحالة المنشورة للعميل، وفصل النشر عن حالة الدفع إذا احتاج التصميم ذلك.
- [ ] إصلاح مفاتيح next-intl في العربية والإنجليزية والرجوع الآمن عند وجود حالة قديمة غير معروفة؛ لا تعرض المفتاح الخام للمستخدم.
- [ ] توحيد مكوّن/تنسيق الحالة بين جدول الفواتير والتفاصيل والمعاينة، مع ألوان واضحة.
- [ ] استخدام عملة الفاتورة الفعلية في الإجمالي والمدفوع والمتبقي والبنود؛ لا رمز دولار ثابت.
- [ ] فصل العملات في ملخص الحسابات عند وجود فواتير بعملات متعددة؛ لا جمع EGP وUSD وEUR في رقم واحد.
- [ ] الحفاظ على Decimal/Minor Units للحساب؛ التنسيق لا يغير القيمة المحاسبية أو Snapshot.
- [ ] مراجعة الموبايل وRTL/LTR وعدم قص شارة الحالة أو إخفاء رمز العملة.

- [ ] لا تغيير لقيم الفواتير أو المدفوعات أو النسخ المنشورة كأثر جانبي.
- [ ] المجاميع المختلطة مفصولة حسب العملة، دون تحويل تلقائي غير موثق.
- [ ] تحقق بصري من شاشات شبيهة بالصور المرفقة باللغتين والموبايل.
