# 09 — اختبارات التكامل والترحيل والنشر والتسليم

الحالة: لم تبدأ. يعتمد على: 01–08.

## المطلوب

التحقق من المنظومة كاملة قبل النشر، وتسجيل ما اكتمل فعلًا وما بقي، بحيث يمكن الاستئناف دون الاعتماد على المحادثة.

## سيناريوهات قبول شاملة

- [ ] عميل جديد ومسار بعرض سعر: عرض وقبول ثم تنفيذ خدماته الفعلية وفاتورة Draft، ثم معاينة ونشر.
- [ ] عميل حالي ومسار مباشر: UCR/ACID عند الحاجة، ثم تحديث الخدمات دون عرض سعر إجباري، ثم نشر الفاتورة.
- [ ] طلب نقل فقط، وطلب تخليص فقط، وطلب متعدد الخدمات: لا مراحل إجبارية غير مختارة.
- [ ] ربط A ثم B: فاتورة حالية واحدة، والقديمة باقية في التاريخ المالي المشروع، ولا حذف أو فقد دفعات.
- [ ] استبدال منشورة بمسودة: لا إشعار يكشف المسودة ولا زر معاينة حتى نشرها.
- [ ] تعيين منشورة: إشعار واحد ورابط صالح للعميل الصحيح. إعادة الربط لا تكرر الإشعار.
- [ ] نشر مراجعة: العميل يرى النسخة القديمة حتى نشر الجديدة، ثم إشعار واحد صحيح.
- [ ] موظف مسؤول بصلاحية تشغيل فقط، موظف حسابات، أدمن، وعميلان مختلفان: مراجعة الواجهة وكل API وPDF والتوكن.
- [ ] العدّادات لكل مستخدم: حفظ/نشر/قراءة/حدث يصل أثناء القراءة/تحديث لاحق/تسجيل دخول جديد.
- [ ] الحالة والعملة والترجمة والتنقل والواجهات على الموبايل وRTL/LTR.
- [ ] الطلبات والفواتير القديمة تستمر دون إعادة تفعيل حسابات أو تغيير حالات تحقق العملاء بسبب النشر.

## خطة الترحيل

- [ ] نسخة احتياطية قبل أي تعديل بيانات أو قيد فريد.
- [ ] تقرير علاقات الفواتير المتعددة الحالية، وقرار موثق لكل تعارض قبل تطبيق قيد المهمة 01.
- [ ] ترحيل متكرر التشغيل بأمان، قابل للمراجعة، ولا يعيد ربط فواتير تم اختيارها لاحقًا.
- [ ] مقارنة عدد الفواتير والمدفوعات وSnapshots وحالات حسابات العملاء قبل وبعد.
- [ ] خطة رجوع معتمدة لا تحذف فواتير أو دفعات حدثت بعد النشر.

## الفحص والنشر

- [ ] تشغيل اختبارات الصلاحيات والحسابات والنشر والربط والإشعارات والحالات، وتسجيل الأوامر والنتائج الفعلية.
- [ ] ESLint والتحقق من الأنواع وبناء النسخة الحالية في بيئة معزولة دون نسخ أسرار إلى المخرجات.
- [ ] اختبار HTTP على بيئة التجربة المنفصلة، مع بيانات اختبار واضحة لا تُنشأ على الإنتاج.
- [ ] فحص بصري للواجهات؛ إذا تعذر، سجل الحد صراحة ولا تدّعِ أنه تم.
- [ ] النشر عند الوصول لمرحلة التنفيذ المصرح بها؛ إنشاء هذه الخطة وحده لا يطلق نشرًا.
- [ ] فحص قراءة على الإنتاج بعد النشر، دون نشر فاتورة حقيقية أو تبديل ربط طلب لاختبار الميزة.
- [ ] تحديث وثائق التنفيذ وتقرير النسخة المنشورة ومعايير القبول ودليل الاستخدام.

## تقرير التسليم المطلوب

1. المهام المكتملة والمكتملة محليًا فقط والمعلقة، وأسباب التعليق.
2. الملفات المعدلة وأي migrations والقرارات المؤثرة على البيانات.
3. نتائج الاختبارات وبيئة كل اختبار، ومعرّف النسخة المنشورة إن نُشرت.
4. ما يحتاج المستخدم فعله لاختيار الفاتورة الحالية للطلبات المتعارضة أو لضبط الصلاحيات.
5. نقطة الاستئناف التالية بدقة، دون أسرار أو كلمات مرور أو توكنات.
